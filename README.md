# Quant Price Live 6.3

Учебный проект на C++17 и Qt 6 для просмотра российских акций и расчёта показателей по ценовым рядам. Приложение показывает котировки и свечи MOEX, строит графики и рассчитывает индикаторы. В лаборатории можно проверить правила виртуальной стратегии на истории и сохранить отчёт.

По умолчанию используется публичный MOEX ISS без регистрации. Его данные поступают с задержкой. Для автономного знакомства есть ДЕМО с синтетическими ценами. Программа не отправляет реальные торговые поручения.

## Интерфейс 6.2

Стартовый экран с выбором задачи; отдельные котировки и исследование; последовательные шаги слева и понятное следующее действие. Источник, акция и фактические даты видны постоянно. Есть готовые правила стратегии, краткие карточки результата, раскрываемые подробности и словарь терминов. Изменённый набор/устаревший результат явно отмечаются. Экспертные параметры скрыты по умолчанию, колесо мыши не меняет поля без фокуса.

Первое знакомство: **Начало → Открыть учебное ДЕМО → Проверить данные → Анализ → Стратегия → Рассчитать и открыть результат**. [Подробный маршрут](WORKBENCH_GUIDE_RU.md).

## Учебные задания

Кнопка «Учебные задания» (Ctrl+4) открывает три автономных синтетических примера: комиссии, стоп/гэп и подбор SMA с отдельным проверочным участком. Пользователь выбирает предположение и параметр, получает численный расчёт, график и объяснение. Задания используют движок лаборатории, работают без аккаунта и не меняют рабочее исследование. [Инструкция](WORKBENCH_GUIDE_RU.md).

## Портфель

В «Портфеле» до шести акций используют общий виртуальный капитал. Доступны исторический бэктест, пошаговый тренажёр и новые закрытые свечи MOEX без ключей; есть шаблоны SMA/RSI, издержки, ребалансировка и ограничения риска. Данные MOEX задержаны, исполнение виртуальное и ретроспективное. `.qpp.json` сохраняет входной проект, `.qpa.json` — проверяемое состояние счёта с позициями и журналом. Открытие файла работает без сети; сетевое продолжение разрешается отдельно. Автосохранения нет. [Правила и ограничения](WORKBENCH_GUIDE_RU.md).

## Автоматические проверки

При каждом push и pull request GitHub Actions собирает проект в Windows и Linux, запускает CTest и Google Benchmark. В Linux дополнительно выполняются проверки ASan и UBSan. Результаты бенчмарка выводятся в журнал и сохраняются в JSON-артефактах `benchmark-Linux` и `benchmark-Windows`.

После успешных сборок генерируется документация Doxygen. Для основной ветки `main` она автоматически публикуется на GitHub Pages. Windows-сборка также упаковывается с библиотеками Qt и проходит автономные проверки готового пакета.

## Быстрый запуск Windows

1. Откройте успешный запуск GitHub Actions.
2. Скачайте артефакт `QuantPriceLive-Windows-x64`.
3. Полностью распакуйте ZIP, сохранив DLL и подпапки.
4. Запустите `START_QUANT_PRICE_LIVE.cmd` или `quant_price_live.exe`.

Компилятор для готового пакета не нужен. На чистом компьютере может потребоваться [Microsoft Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe). Commit сборки указан в `VERSION.json`.

Для примера без сети: «Начало → Открыть учебное ДЕМО → Анализ → Стратегия → Рассчитать и открыть результат». Подробный маршрут и словарь терминов — в [гайде](WORKBENCH_GUIDE_RU.md).

## Сборка из исходников

Сначала скачайте исходники и перейдите в папку проекта:

```bash
git clone https://github.com/Archibald02/Vega-C-Novikov.git
cd Vega-C-Novikov
```

Команды ниже выполняются из этой папки. Windows ZIP содержит готовое приложение; для сборки используйте исходники репозитория.

Нужны Git, CMake 3.20+ и компилятор с поддержкой C++17. Для интерфейса требуется Qt 6.5+ с Widgets, Network, WebSockets и Concurrent. В CI используется Qt 6.8.3. При первой конфигурации CMake скачивает doctest 2.4.12 и Google Benchmark 1.9.4.

### Windows

Пример для MSVC 2022 и Qt 6.8.3 MSVC 2022 64-bit. Выполните в Developer PowerShell из корня репозитория, указав свой путь к Qt:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build build --config Release --parallel 2
$env:PATH = "C:\Qt\6.8.3\msvc2022_64\bin;" + $env:PATH
ctest --test-dir build -C Release --output-on-failure
.\build\Release\quant_benchmark.exe --benchmark_min_time=0.1s
.\build\Release\quant_price_live.exe
```

### Linux

Нужны Qt и dev-пакеты OpenGL. Укажите путь к установленному Qt:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/path/to/qt/gcc_64
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/quant_benchmark --benchmark_min_time=0.1s
./build/quant_price_live
```

Для сборки численного ядра, его тестов и бенчмарка без Qt:

```bash
cmake -S . -B build-core -DCMAKE_BUILD_TYPE=Release -DBUILD_GUI=OFF
cmake --build build-core --parallel 2
ctest --test-dir build-core --output-on-failure
./build-core/quant_benchmark --benchmark_min_time=0.1s
```

Тесты не требуют брокерского токена и доступа к рыночным данным. Автономные GUI-проверки выполняются через CTest с `QT_QPA_PLATFORM=offscreen`.

## Что проверяют тесты и бенчмарк

Unit-тесты на doctest проверяют формулы доходности, SMA, волатильности, работу скользящих окон и обработку некорректных входов. Полный CTest содержит 11 групп: численное ядро, индикаторы, стратегии, разбор API, сетевые ошибки, приватность, интерфейс и нагрузку ограниченной истории. Тесты сети используют локальный тестовый сервер и синтетические ответы; подключения к бирже для CI не нужны.

Например, для цен `100, 110, 99` тест ожидает доходности `0.1` и `-0.1`. Скользящее окно сравнивается с пакетным расчётом после добавления и вытеснения наблюдений.

Google Benchmark выполняет 13 комбинаций измерений: пакетные расчёты, обновление окна и индикаторов, прогноз, тесты стационарности и бэктест. Подготовка исходных рядов вынесена за измеряемые циклы. Замеры относятся к вычислениям и не включают сеть и отрисовку интерфейса.

## Возможности и ограничения

В приложении есть таблица котировок, свечные графики, SMA/EMA/RSI/MACD/Bollinger и лаборатория анализа исторических данных. Лаборатория поддерживает виртуальный бэктест с издержками, walk-forward, финальный проверочный участок, сравнение параметров и стресс-сценарии. Настройки и результаты можно явно экспортировать в локальные файлы проектов и отчётов.

Потоковые индикаторы считаются по принятым обновлениям цены; свечные индикаторы рассчитываются отдельно. Разброс нерегулярных обновлений не выдаётся за годовую волатильность. Результаты на истории и учебные прогнозы не гарантируют будущую доходность. Полный биржевой календарь и корректировки на корпоративные события не гарантируются.

Дополнительный режим АЛОР требует торгового аккаунта и ручного ввода токена. Токены не сохраняются и не нужны для CI. Автоматически сохраняются только безопасные настройки интерфейса. Котировки, виртуальный капитал и сделки попадают в локальные проекты и отчёты только по явной команде пользователя. Правила описаны в [PRIVACY.md](PRIVACY.md).

## Готовый выпуск и дальнейшее обновление

Все накопленные функции исследовательской платформы включены в `main` и общий выпуск 6.3.0. Скачивайте Windows ZIP со страницы [Releases](https://github.com/Archibald02/Vega-C-Novikov/releases/latest), распаковывайте целиком в новую папку и запускайте `START_QUANT_PRICE_LIVE.cmd`. `Code → Download ZIP` содержит исходники; ранее скачанный EXE сам не обновляется. [Состав выпуска и установка](RELEASE_NOTES_RU.md).

Публикация Releases выполняется CI только для проверенной `main`, после тестов, санитайзеров, упакованного GUI и документации. Черновик публикуется после повторного скачивания и сверки архива. Существующие публичные assets не перезаписываются. Для нового выпуска необходимо согласованно повысить версию в CMake, приложении и манифесте Windows-пакета CI, обновить описание выпуска; существующий тег другой версии кода повторно не используется. Повторный запуск того же проверенного commit проверяет и сохраняет уже опубликованный пакет.

## Поиск и настройка рабочего места (6.2)

Нажмите **Ctrl+K** или «Поиск» в заголовке. Поиск охватывает 22 раздела: вводите русские слова или сокращения, например `корреляции`, `ATR`, `ADF KPSS`, `walk-forward`, `портфель`. Несколько слов уточняют запрос. Стрелки ↑/↓ выбирают результат, Enter открывает раздел, Esc закрывает окно. Для расширенной аналитики раскрывается экспертный блок; прокрутите страницу до нужной таблицы. Поиск не нажимает «Рассчитать» и не запускает подключение; уже запущенные фоновые задачи продолжаются. Запрос и история переходов не записываются.

В «Настройки и помощь → Производительность и параметры потока» появились **основной текст 13–18 px**, три готовых вида таблицы котировок и отдельный выбор пяти дополнительных колонок. Заголовки и подписи графиков могут иметь собственный размер. Тикер, цена, время данных и возраст ответа всегда остаются видимыми. Это помогает видеть задержку; скрытые колонки продолжают рассчитываться. Размер текста и вид таблицы сохраняются локально, без цен, капитала и токенов. «Сбросить вид» возвращает 13 px и все колонки; общая очистка локальных данных удаляет и эти настройки.

Клавиши **Ctrl+1…5** открывают начало, котировки, исследование, учебные задания и портфель. Поиск доступен с любой основной страницы. На малом экране используйте прокрутку; темы оформления и перестановка колонок остаются в плане.

## Временные правила и фактическое исполнение (6.3)

В «Исследование → Стратегия» доступны четыре строки для входа и четыре для выхода. Отмеченные строки соединяются «все» или «любое». Вложенные группы, частичные плановые выходы и старший интервал пока не реализованы.

Блок «Подтверждение, пауза и время исполнения» задаёт подтверждения 1–50 подряд, паузу 0–500 полных закрытий после выхода, срок удержания 0–5000 свечей и дополнительную задержку сигнала 0–10 свечей. По умолчанию: 1/1/0/0/0 — прежняя стратегия. Ложная группа сбрасывает подтверждение; непрогретый индикатор не считается истинным. Пересечение само по себе истинно одну свечу: выдержка >1 для такого условия обычно не даёт сигнала. Для длительного состояния выбирайте «больше/меньше».

Свеча выхода не расходует паузу. Например, после выхода на свече 10 при паузе 2 закрытия 11 и 12 блокируются; новый сигнал возможен на закрытии 13, покупка — на открытии 14. Подтверждения во время паузы не накапливаются. Срок удержания включает свечу покупки: срок 1 означает выход на открытии следующей свечи. Он отменяет задержку обычного выхода. При недоступном объёме выход может растянуться — срок не гарантирует ликвидацию. Стоп, цель и аварийные выходы работают независимо от подтверждения, паузы и обычной задержки. Подтверждённый сигнал фиксируется до исполнения; будущие условия его не отменяют. В модели «купить и держать» новые временные ограничения стратегии отключены.

В «Результат» раскройте «Почему возникла или не возникла сделка?» и выберите свечу. Показаны исходные условия и фактическое состояние модели: подтверждения, пауза, ожидание, позиция и деньги до/после, триггер, исполненное количество, модельная цена, комиссия и ухудшение цены. Это значения завершённого расчёта; редактирование настроек их не меняет. При касании стопа и цели в одной свече остаётся явно выбранное допущение порядка. Невыполненный остаток покупки отменяется; выход при ограниченном объёме повторяется на последующих открытиях. Исправлено наследование задержки обычного сигнала защитным выходом после нулевого объёма.

Полная трассировка экспортируется в HTML и проверяемый снимок .qps; PDF ограничен первыми 500 свечами. Данные и капитал выходят из памяти только при явном экспорте. Новые снимки используют схему 2 и проверяют также трассировку. Схема 1 читает прежние параметры с нейтральными значениями новых фильтров; если изменённая модель защитного выхода не воспроизводит старый нестандартный сценарий, проверка сообщает о несовпадении и не подменяет эталон. Старые проекты без новых полей открываются с выключенными строками 3–4 и фильтрами 1/1/0/0/0.

Эти настройки относятся к движку стратегии одной акции: исходный бэктест, проверки устойчивости и виртуальный счёт. Подробная трассировка сохраняется для исходного бэктеста, а не каждого запуска подбора. В отдельном портфельном движке этих пяти фильтров пока нет. Лимиты: 5000 свечей, до четырёх попыток/исполнений на свечу, до 10000 событий основного журнала; новые параметры не добавляют таймеров или сетевых запросов.
