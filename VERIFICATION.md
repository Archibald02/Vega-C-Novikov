# Проверка версии 3

Дата локальной проверки: 27 октября 2026. Linux, GCC 13.3, Qt 6.8.3, Release.

- Успешно собраны все цели CMake.
- CTest: 6/6 — базовые формулы, индикаторы/прогнозы/риск, API payload и каталог, GUI smoke, вкладки/пороги/простой графика, ограниченная история.
- Stress: 500 000 наблюдений по 20 инструментам. Все истории достигли лимита, выделенный размер кольцевых буферов не изменился.
- GUI tools проверяет прогноз с MAE, расчёт 20 лотов, одноразовый порог, переключение оверлеев и отсутствие дополнительных пересозданий кэша в простое. GUI также отрендерен и визуально проверен.
- Онлайн-проверки без ключей: каталог 505 действующих TQBR инструментов и реальные ответы MOEX. Публичные цены задержаны; это не проверка real-time.
- Google Benchmark: 11 результатов в JSON. Doxygen HTML сформирован без предупреждений.

## Нагрузка

Измерение внутри процесса в режиме `--profile`: 20 демонстрационных инструментов, около 80 наблюдений/с, история 2000, график 2 кадра/с, 15 секунд, Qt offscreen. CPU — доля одного ядра, RAM — resident set всего процесса.

После первого отсчёта: CPU 0,5–1,2%, RAM 48,3–48,5 МиБ. Первый отсчёт с инициализацией: 5,8% и 46,4 МиБ. За 15 секунд 29 пересозданий кэша графика. Предвыделенная история 20 акций: 2,75 МиБ. Это короткий локальный замер, не гарантия расхода в Windows или при другом потоке/масштабе экрана. Сравнение с предыдущей версией в одинаковых условиях не проводилось.

Микротесты: потоковые индикаторы около 42 нс/обновление для окон 20 и 500; прогноз с ретропроверкой 500 цен около 8,9 мкс. Эти цифры измеряют численное ядро, не весь интерфейс/сеть.

## Воспроизводимость

```
ctest --test-dir build -C Release --output-on-failure
quant_price_live --profile
quant_price_live --stress-test
quant_price_live --check-catalog
quant_price_live --check-moex
```

Для Linux без дисплея задайте QT_QPA_PLATFORM=offscreen. Тесты CI используют только синтетические цены и fixtures; ключи не нужны. Windows и Linux проверяются в [GitHub Actions](https://github.com/Archibald02/Vega-C-Novikov/actions). Windows дополнительно проверяет запуск упакованного приложения с локальными DLL. Результат актуального запуска следует проверять по его commit SHA.

АЛОР: протокол и разбор сообщений покрыты локальными проверками, но реальный боевой токен и права аккаунта здесь не проверялись. Полный нагрузочный/сетевой сценарий с брокерским потоком требует локального теста пользователя. Токен в репозиторий не добавлять.
