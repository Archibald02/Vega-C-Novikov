# Полный гайд: Quant Price Live, Windows и GitHub

## 1. Что изменилось

Это приложение с обычным окном Windows: таблица акций, график и настройки.
CSV не требуется. Можно смотреть интернет-котировки MOEX ISS без ключа,
подключить поток АЛОР с токеном или проверить интерфейс в демонстрации.
Все исходники, тесты, CMake, benchmark, Doxygen и CI/CD входят в комплект.

Важное различие источников:

| Источник | Что нужно | Что показывает |
|---|---|---|
| АЛОР | Боевой аккаунт и Refresh token | Подписки на поток котировок российских акций |
| MOEX ISS | Только интернет | Реальные биржевые данные, доступные с задержкой |
| ДЕМО | Ничего | Синтетические цены для знакомства с окном |

Использование OpenAPI АЛОР заявлено бесплатным в FAQ брокера. Для реального потока
одной регистрации разработчика недостаточно: нужен торговый аккаунт.
Условия брокерского обслуживания проверяются отдельно. Тестовый контур передаёт
симуляционные данные; в этом приложении он не используется.

В исходном архиве **нет готового Windows EXE**. Его автоматически создаст GitHub Actions.
Это позволяет получить приложение без установки C++ и Qt на собственный компьютер.
Windows-пакет пока не собран в вашем аккаунте — это нужно сделать по разделу 2.

## 2. Получить Windows-приложение через GitHub — рекомендуемый первый путь

1. Распакуйте архив в удобную папку. Внутри найдите CMakeLists.txt, app, src, include,
   tests, benchmarks и папку .github. Именно эта папка — корень проекта.
2. В GitHub нажмите `+` → New repository. Имя **quant-price-live**, видимость **Public**.
   Включите создание README, затем Create repository.
3. Проверьте, что основная ветка называется **main**.
4. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
   Создавать предложенный шаблон workflow не нужно — он уже есть в комплекте.
5. В локальном README.md замените Archibald02 своим логином. Если у репозитория
   другое имя, измените и имя в ссылке документации.
6. Вернитесь на вкладку Code → Add file → Upload files. Перетащите **содержимое**
   корня проекта, включая .github, а не внешнюю папку целиком. CMakeLists.txt
   должен оказаться непосредственно в корне репозитория.
7. Напишите сообщение `Add live C++ Qt application`, затем Commit changes в main.
8. Убедитесь, что в репозитории есть `.github/workflows/ci.yml`.
   Если .github не загрузилась, Add file → Create new file → имя `.github/workflows/ci.yml`,
   вставьте точное содержимое файла из комплекта и сохраните.
9. Откройте Actions → **Build, test, benchmark and docs**. Если GitHub предлагает
   включить workflows, включите. Дождитесь завершения. Установка Qt при первом
   запуске может занять несколько минут; это установка среды сборки, не задержка приложения.
10. Проверьте оба build: Ubuntu и Windows. Затем documentation и deploy.
11. На странице запуска внизу найдите **Artifacts → QuantPriceLive-Windows-x64**.
    Нажмите, скачайте ZIP и полностью распакуйте в отдельную папку.
12. Запустите **quant_price_live.exe** двойным щелчком.
    Не вытаскивайте один EXE из папки: рядом нужны DLL и подпапки платформенных плагинов.

Если приложение сообщает об отсутствии VCRUNTIME/MSVCP, установите официальный
**Microsoft Visual C++ Redistributable x64**:
https://aka.ms/vs/17/release/vc_redist.x64.exe

Сборка не подписана сертификатом издателя. При предупреждении Windows сверяйте
происхождение файла с вашим собственным workflow, а не скачивайте заменяющие DLL с сайтов.

Если репозиторий уже создан для первой версии, можно использовать его. Скопируйте
новые файлы поверх рабочей копии, обновите README и workflow. Старые src/main.cpp,
src/csv.cpp и data/prices.csv больше не используются и их можно удалить.
Если имя осталось quant-price-lab, ссылка Pages должна содержать quant-price-lab.
Для работы через GitHub Desktop см. раздел 8.

## 3. Первый запуск: убедиться, что интерфейс работает

1. В поле «Источник» выберите **ДЕМО — синтетические цены**.
2. Оставьте SBER, GAZP, LKOH, YDEX.
3. Нажмите **Подключить**. Появятся меняющиеся строки и график.
4. Щёлкните другую строку — переключится график и карточки её показателей.
5. Нажмите **Отключить**. Значения останутся видимыми, счётчик времени с ответа растёт.

Демо явно подписано: это не реальные цены акций.

Теперь выберите **MOEX ISS — с задержкой, без ключа** и нажмите Подключить.
Программа получит котировки по интернету. Загрузка идёт асинхронно: окно доступно,
пока сервер отвечает. Обновления запрашиваются каждые 5 секунд.

У MOEX ISS есть задержка биржевых данных. Опрос раз в 5 секунд её не убирает.
«Время данных» в этом режиме — время снимка ISS, не время последней сделки.
Вне торгов цены могут не меняться. Ошибка или отсутствие LAST не заменяются вымышленной ценой.

## 4. Как подключить живой поток АЛОР

Официальный пошаговый источник:
https://alor.dev/docs/api/quick-start/prod-env

1. Создайте отдельную учётную запись разработчика на https://alor.dev/ и подтвердите email.
2. В разделе https://alor.dev/open-api-tokens привяжите действующий торговый аккаунт
   по инструкции провайдера. Если такого аккаунта нет, доступ к боевому потоку пока не появится.
3. На странице токенов выпустите **Refresh token для боевого контура**.
4. В приложении выберите **АЛОР — WebSocket, боевой аккаунт**.
5. Вставьте Refresh token в скрытое поле «Токен АЛОР».
6. Оставьте, например, `SBER, GAZP`, интервал «Поток» 250 мс, окно 20.
7. Нажмите Подключить. Сначала идёт авторизация, затем открытие WebSocket и подписки.
8. Во время торгов должны появиться котировки. Если подписка отклонена,
   проверьте тип токена, аккаунт, права и тикеры. Нажмите Отключить перед повторной попыткой.

Программа сама получает краткосрочный AccessToken и обновляет соединение каждые 25 минут.
Вручную копировать AccessToken вместо Refresh token не нужно.
Токен не сохраняется в настройках и очищается из поля после отключения;
после перезапуска его надо ввести снова. Не присылайте его в чат, не помещайте
в исходники, скриншоты, репозиторий или GitHub Secrets для этого проекта.
Для чтения котировок нет необходимости добавлять торговые функции в код.

Параметр 250 мс задаёт интервал выдачи сообщений у провайдера. Это не обещание
задержки 250 мс от биржи до экрана. Нет новых сделок — последняя цена может не изменяться.
При сетевом обрыве идут автоматические повторы с увеличением интервала до 30 секунд.
Если токен отозван или неверен, соединение останавливается с сообщением об ошибке.

## 5. Что означают таблица, график и настройки

- **Тикеры** — от 1 до 20 инструментов режима TQBR; разделители — запятая, пробел, `;`.
  Набор зависит от доступности у источника. Это не универсальный поиск всех рынков и бордов.
- **Цена** — последняя переданная цена сделки или снимка.
- **Bid / Ask** — лучшие переданные цены спроса и предложения. `—` означает отсутствие поля.
- **Изм. дня** — процент изменения относительно предыдущего закрытия из ответа источника.
- **Время данных** — дата и время данных, отображённые в локальном часовом поясе компьютера.
  АЛОР: время последней сделки; ISS: SYSTIME снимка.
- **Ответ, с** — сколько секунд прошло после приёма последнего подходящего ответа для тикера.
  Это не сетевая задержка и не доказательство свежести биржевой цены.
- **SMA / σ: N цен** — размер расчётного окна, от 3 до 2000. Во время прогрева
  среднее считается по имеющимся ценам, карточка показывает фактическое количество.
- **σ доходностей обновлений** — выборочное стандартное отклонение относительных
  изменений между принятыми ценами. Оно показано в процентах и не является годовым.

График строится с момента подключения и хранит последние 2000 точек на тикер.
История перед запуском не загружается. Это обеспечивает быстрый старт без CSV и больших файлов.
Одинаковые время и цена не добавляют повторную точку; устаревшие сообщения отбрасываются.
Перерисовка происходит до 4 раз в секунду независимо от приёма данных.

Чтобы изменить источник, тикеры или параметры, сначала нажмите Отключить.
После нового подключения графики и расчётные окна начинаются заново.
Приложение сохраняет только выбранные тикеры и настройки, а не полученные цены.

## 6. Локальная сборка Windows — если хотите менять и запускать код

Установите Git for Windows, CMake с добавлением в PATH и Visual Studio Build Tools 2022
с компонентом **Desktop development with C++**, MSVC и Windows SDK:

- Git: https://git-scm.com/download/win
- CMake: https://cmake.org/download/
- Build Tools: https://visualstudio.microsoft.com/downloads/

Нужен также Qt 6.8.3 MSVC 2022 64-bit с Qt WebSockets.
Один из способов установить его — бесплатный инструмент aqtinstall. С установленным Python:

```powershell
py -m pip install aqtinstall
py -m aqt install-qt windows desktop 6.8.3 win64_msvc2022_64 -m qtwebsockets -O C:\Qt
```

Ожидаемая папка: `C:\Qt\6.8.3\msvc2022_64`. Проверьте наличие bin\qmake.exe
и bin\Qt6WebSockets.dll. Если выбран другой путь, измените команды ниже.
Этот способ не требует аккаунта Qt; используйте исходные открытые пакеты.

Откройте **Developer PowerShell for VS 2022**, затем:

```powershell
cd C:\Projects\quant-price-live
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build build --config Release --parallel 2
$env:PATH = "C:\Qt\6.8.3\msvc2022_64\bin;" + $env:PATH
ctest --test-dir build -C Release --output-on-failure
.\build\Release\quant_price_live.exe
```

При первой конфигурации CMake скачает doctest и Google Benchmark. Это однократная
подготовка сборки, не часть каждого запуска программы. Для Windows используйте именно
комплект Qt MSVC, не MinGW, если собираете приведёнными командами MSVC.

## 7. Тесты, benchmark, документация и упаковка

Unit-тесты и автономная проверка окна:

```powershell
ctest --test-dir build -C Release --output-on-failure --verbose
```

Проверки не требуют токена и сети. Успех: 100% tests passed.
Большое число assertions связано с проверкой скользящего окна на каждом из 10 000 шагов,
это не такое же число отдельных сценариев.

Benchmark:

```powershell
.\build\Release\quant_benchmark.exe --benchmark_min_time=0.1s
.\build\Release\quant_benchmark.exe --benchmark_min_time=0.1s --benchmark_out=build/benchmark.json --benchmark_out_format=json
```

8 строк измерений: пакетные доходности, SMA и волатильность на двух размерах входа;
обновление RollingSeries для окон 20 и 2000. Time и CPU — время, Iterations — повторы.
Это проверка вычислений, не задержки интернет-канала.

Для папки с EXE и библиотеками Qt:

```powershell
New-Item -ItemType Directory -Force dist
Copy-Item .\build\Release\quant_price_live.exe .\dist\
& "C:\Qt\6.8.3\msvc2022_64\bin\windeployqt.exe" --release --no-translations --no-compiler-runtime .\dist\quant_price_live.exe
Copy-Item .\licenses .\dist\licenses -Recurse -Force
Copy-Item .\THIRD_PARTY.md,.\LICENSE .\dist\
.\dist\quant_price_live.exe
```

Для переноса нужна вся dist, включая лицензии и plugins. На другом компьютере установите
официальный Visual C++ Redistributable, если его ещё нет. Qt в PATH там не требуется.
CI делает упаковку автоматически и сохраняет artifact.

Для Doxygen установите его с https://www.doxygen.nl/download.html и выполните из корня:

```powershell
doxygen Doxyfile
Start-Process .\build\docs\html\index.html
```

Graphviz не требуется. В CI документация создаётся автоматически и публикуется в main.

## 8. Как обновлять репозиторий и что проверять в Actions

Удобный вариант — GitHub Desktop: https://desktop.github.com/
Войдите → File → Clone repository → выберите свой репозиторий → клонируйте в новую папку.
Изменяйте файлы этой копии. Для переноса комплекта скопируйте его содержимое в корень
копии, сохранив служебную .git. Затем проверьте diff в Desktop → Commit to main → Push origin.
Commit без Push не запускает удалённые проверки.

В Actions у последнего запуска должны быть успешны:

1. build в Linux и Windows: сборка, unit-тесты, payload-тесты, GUI smoke test, benchmark.
2. В Windows — Package Windows application и Check packaged GUI.
3. documentation — Doxygen HTML.
4. deploy — GitHub Pages.

Внизу доступны artifacts: `QuantPriceLive-Windows-x64`, `benchmark-Windows`,
`benchmark-Linux`, `doxygen-html`. Время benchmark видно прямо в шагах журнала.
Если запуск упал после настройки Pages, используйте Re-run all jobs, либо
Actions → выбранный workflow → Run workflow → main.

GitHub Pages публикует документацию, а не само Windows-приложение.
Не загружайте папки build, dist, Qt SDK, токены и личные данные в репозиторий.

## 9. Частые проблемы

| Проблема | Что проверить |
|---|---|
| Actions не появляется | Путь .github/workflows/ci.yml; push; разрешение GitHub Actions |
| CMake не видит Qt6 | CMAKE_PREFIX_PATH указывает на папку msvc2022_64, где есть lib/cmake/Qt6 |
| Не найден Qt6WebSockets | Модуль qtwebsockets установлен именно для выбранной версии/комплекта |
| Ошибка Visual Studio generator | Установлен Build Tools 2022 с C++; запускается Developer PowerShell |
| Старый build мешает | Удалите только сгенерированную папку build и повторите конфигурацию |
| EXE не видит Qt6 DLL | Запуск из dist после windeployqt либо Qt bin добавлен в PATH терминала |
| Не найден VCRUNTIME/MSVCP | Установите официальный Visual C++ Redistributable x64 |
| Не найден платформенный plugin | Распакуйте весь artifact, сохраните подпапку platforms рядом с EXE |
| MOEX без цены | Проверьте тикер, TQBR, соединение и доступность LAST; другой тикер может работать |
| MOEX цена «старая» | Этот источник с задержкой; частый опрос не делает его real-time |
| АЛОР не авторизуется | Нужен Refresh token боевого контура, а не AccessToken/тестовый токен |
| Поток открыт, цены стоят | Проверьте торговую сессию и ликвидность; следите за временем данных |
| После ошибки кнопка Подключить недоступна | Нажмите Отключить, проверьте настройки, подключите повторно |
| Pages 404 | Source=GitHub Actions, ветка main, успешный deploy, правильная ссылка README |

Не отключайте проверку TLS и не вставляйте токены в URL ради отладки.
При сетевом сбое программа не подменяет реальные котировки демонстрационными.
Если у вас уже есть аккаунт другого брокера, для его API понадобится отдельный адаптер:
вставка произвольного адреса сайта в эту версию не поддерживается.

## 11. Объяснение для защиты

- «Приложение получает котировки через асинхронные API. В UI нет ожидания сети».
- «АЛОР использует WebSocket; MOEX ISS — HTTP-опрос с задержкой данных».
- «Скользящее окно обновляется за постоянное время; история ограничена по размеру».
- «Тесты проверяют математику, удаление старых наблюдений и разбор сообщений».
- «Benchmark измеряет вычисления отдельно от сети и интерфейса».
- «σ по нерегулярным обновлениям не выдаётся за годовую волатильность».
- «CMake описывает цели, а CI собирает приложение и создаёт Windows artifact».
- «Doxygen документирует публичный API, Pages публикует HTML».
- «Ключ не хранится в репозитории, тесты CI не зависят от брокерского счёта».

Подробные формулы и ограничения находятся в docs/theory.md.
Покажите таблицу с источником, переключение графика, расчёт RollingSeries, один тест,
зелёный Actions, журнал benchmark и страницу документации.
