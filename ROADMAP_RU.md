Первые поставки: объяснение сигналов → сохранённые эксперименты → учебные примеры. Затем общий портфельный движок и расширенные правила, после них данные/события и масштабирование. Трассировка реального модельного исполнения дополняет объяснение условий отдельным этапом.

Общие требования: только виртуальные сделки; MOEX без обязательных аккаунтов; синтетические и задержанные данные явно отмечены; токены не записываются; локальный кэш и автосохранение включаются пользователем. Фоновая работа, ограниченная память и очереди, отмена, контроль численных эталонов. Для каждого опубликованного выпуска обязательны Windows/Linux CI, GUI, санитайзеры и проверка упакованного приложения.

## Следующие этапы после 6.18

- Корпоративные события: сначала подтвердить официальный источник ex-date, даты доступности, валюты, дроблений и полноты. Затем добавить отдельную модель поступлений/корректировки с тестами против двойного учёта. Текущая дата реестра не заменяет ex-date; отсутствие ответа не означает отсутствие дивидендов.
- Портфель: перенос произвольных формул и ограничений исполнения из одиночного движка требует новой версии модели и повторения старых счетов в прежней модели. Уже доступные шаблоны SMA/RSI сохраняются.
- Календари: внутридневные сессии и приостановки конкретной акции остаются неизвестными без отдельного источника; дневная сверка не классифицирует их автоматически.
- Производительность: сравнить новые бенчмарки на одинаковом оборудовании, измерить задержку отмены/отклика и RAM. После этого выбирать кэш и число потоков; сам факт фонового запуска не доказывает отзывчивость.
- Выпуски: установщик с проверкой зависимостей на чистой Windows и явные миграции форматов проектов/счетов. Чтение старых снимков 1–5 уже сохранено; оно не является миграцией всех форматов.
- GitHub: владелец/администратор должен включить защиту main с обязательными проверками Linux, Windows и документации. Настройка репозитория не переносится через файлы PR и не меняется правами обычного write-доступа.
